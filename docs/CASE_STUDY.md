# LumenWatch: обнаружение изменений с проверяемой историей

## Задача и мой вклад
Самостоятельный портфолио-проект мониторинга сайтов, использовавшийся реальными пользователями. Разработаны FastAPI-сервис, HTTP-сбор содержимого, SQLite-история, сравнение, планировщик, интерфейс и MCP-инструменты. Показанные исходные цели и инциденты вымышлены; масштаб использования не заявляется.

## Сценарий
Добавить URL → выполнить первую проверку → получить baseline → повторить проверку изменившейся страницы → посмотреть различия и извлечённый текст → восстановить историю после перезапуска. В видео используется контролируемая локальная страница, содержание которой действительно меняется между двумя HTTP-запросами.

## Решения
1. HTTP probe извлекает текст Beautiful Soup, удаляет служебные блоки и сравнивает нормализованное содержимое. Для JS-страниц есть необязательный Playwright probe; он требует отдельной установки браузера.
2. Снимки неизменяемые и сохраняются в SQLite вместе со статусом и длительностью. Это позволяет объяснить, чем изменение подтверждается, вместо единственного индикатора на экране.
3. Сравнение выполняется по детерминированным правилам. Severity — эвристика, а не гарантия бизнес-важности; MCP предоставляет инструменты и не означает автономное принятие решений.
4. Планировщик выключен по умолчанию, чтобы клонирование не запускало неожиданные запросы. Ошибка одной цели изолируется от остальных.
5. Названия, URL и извлечённые слова экранируются перед HTML-вставкой; произвольное содержимое целевого сайта остаётся текстом.

## Подтверждение
pytest проверяет базовый снимок, изменения, хранение, API, scheduler и ошибки probe; Ruff проверяет Python. Отдельный Node-тест сохраняет регрессионные примеры HTML/атрибутной инъекции. В браузере проверены добавление цели, два реальных HTTP-снимка и сохранение результатов после перезагрузки.

## Ограничения
Доверенный локальный запуск: нет пользователей и изоляции сетевого периметра. Не следует открывать этот API публично без аутентификации, сетевых ограничений, SSRF-защиты по адресу назначения/редиректам и квот. Начальные данные демонстрационные, browser mode и HTTP mode имеют разные эксплуатационные затраты. Нагрузочные обещания отсутствуют.
